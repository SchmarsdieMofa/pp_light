# pp_light – Roadmap (Meilensteine)

**Spec:** `docs/superpowers/specs/2026-09-30-pp-light-design.md`

Die Spec umfasst mehrere Teilsysteme. Jeder Meilenstein bekommt einen eigenen Implementierungsplan unter `docs/superpowers/plans/` und endet mit lauffähiger, getesteter Software. Den Plan für Meilenstein N+1 schreiben wir erst, wenn N fertig ist. So baut er auf dem echten Code auf statt auf Annahmen.

| # | Meilenstein | Ergebnis (testbar) | Plan |
|---|---|---|---|
| M1 | **Fundament** | Scaffold, Docker (dev + prod), DB-Basis, Login per Passwort, Rechte-Matrix, Projekte anlegen, App-Shell mit Seitenleiste, Hell/Dunkel, E2E-Gerüst | `2026-10-01-m1-fundament.md` |
| M2 | **Aufgaben-Kern** | Tabelle `tasks` + Nummerierung KEY-n, Unteraufgaben (1 Ebene), Checklisten, Labels, Priorität, Zuständige, Listenansicht, Aufgaben-Panel rechts + `/tasks/[id]`, Schnell-Anlegen, `updated_at`-Konfliktprüfung, `activity_log` | folgt |
| M3 | **Kanban** | Board mit dnd-kit, fractional index, optimistisches Drag & Drop mit Rollback, Kartendichte pro Nutzer, Status-Spalten in den Projekteinstellungen verwalten, Mitgliederverwaltung | folgt |
| M4 | **Phasen & Abhängigkeiten** | Phasen/Meilensteine, `task_dependencies` mit `lag_days`, Zyklusprüfung, Arbeitstage-Logik, Auto-Verschieben nur nach hinten, Undo per `group_id` | folgt |
| M5 | **Gantt** | Spike SVAR vs. Frappe, Gantt-Sicht (Tabelle + Zeitachse, Zoom, Heute-Linie, Pfeile, Ziehen → Auto-Verschieben, Hinweis „könnte früher starten“) | folgt |
| M6 | **Kommentare & Anhänge** | Kommentare (Markdown, @Erwähnungen), Uploads ins Volume, geschützter Download, Bildvorschau, Verlauf im Panel | folgt |
| M7 | **Benachrichtigungen, Einladungen, SSO** | pg-boss-Worker, SMTP-Digest, Inbox + Glocke (Polling), Fälligkeits-Cron, Einladung per Mail, Passwort-Reset, OIDC mit Kontoverknüpfung, Admin-Bereich | `2026-10-01-m7-benachrichtigungen-einladungen-sso.md` |
| M8 | **Komfort & Abschluss** | Startseite „Meine Arbeit“, Strg+K mit Volltextsuche, Tastenkürzel, mobile Ansicht, voller E2E-Durchlauf laut Spec, Abnahme `docker compose up` | folgt |

**Abhängigkeiten:** M2 braucht M1. M3 und M4 brauchen M2. M5 braucht M4. M6 und M7 brauchen M2 (M7 nutzt die Auslöser aus M3, M4 und M6). M8 kommt zuletzt.
